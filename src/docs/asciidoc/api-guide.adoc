Vointika's HTTP API. Requests and responses are JSON. Every example below is
generated from the controller documentation tests, so the guide never drifts
from the running service.

[[overview]]
== Overview

[[overview-http-status-codes]]
=== HTTP Status Codes

|===
| Status code | Usage

| `200 OK`
| The request completed successfully.

| `201 Created`
| A new resource was created; its location is in the `Location` header.

| `204 No Content`
| The request completed successfully with no response body.

| `401 Unauthorized`
| Missing or invalid authentication credentials.

| `403 Forbidden`
| Authenticated, but not permitted (e.g. an insufficient tour-operator role).

| `404 Not Found`
| The resource was not found — or is hidden for tenant isolation (a non-member sees the same 404 as a missing operator).

| `409 Conflict`
| The request conflicts with current state (e.g. a duplicate, or an already-accepted invitation).

| `410 Gone`
| The resource is no longer available (e.g. a revoked or expired invitation).

| `422 Unprocessable Content`
| The request body contains invalid fields.

| `429 Too Many Requests`
| A rate limit was exceeded (see <<overview-rate-limiting>>).

| `500 Internal Server Error`
| An unexpected error occurred.
|===

[[overview-errors]]
=== Error Responses

Every error response has the same shape:

|===
| Field | Type | Description

| `status`
| Number
| The HTTP status code.

| `error`
| String
| The HTTP status reason phrase.

| `message`
| String
| A human-readable error message.

| `code`
| String
| Optional stable, machine-readable error code. Present only when the throw site supplies one (certain `422`/`409` errors); omitted otherwise. Clients that branch on a specific cause should match this rather than the human-readable `message`.

| `timestamp`
| String
| When the error occurred (ISO 8601).
|===

[[overview-resource-identity]]
=== Resource Identity

Every resource-representing response identifies itself with two meta fields:

* `id` — the entity's id. Always literally `id`, never a prefixed name.
* `context` — the collection the entity belongs to (`"users"`, `"currencies"`,
  `"timezones"`, …). A team member is a user with a role, so a member row is
  `id` (the user's id) + `context: "users"`.

[[overview-authentication]]
=== Authentication

Authenticated endpoints require a `Bearer` access token:

----
Authorization: Bearer <access-token>
----

Obtain one from <<resources-login>>. A short-lived access token is refreshed via
<<resources-refresh>> using the `httpOnly` refresh cookie. Endpoints under
`/api/tour-operators/{id}/**` additionally require membership of that operator
(a non-member is indistinguishable from a missing operator — both `404`); the
role each action needs (member / ADMIN+ / OWNER) is noted per endpoint.

[[overview-rate-limiting]]
=== Rate Limiting

The public authentication endpoints are rate-limited per IP, with additional
per-account throttles inside the identity flows. Exceeding a limit returns
`429 Too Many Requests`.

=== Tour Operators

[[resources-create-operator]]
==== Create Tour Operator

The authenticated caller becomes the operator's OWNER.

operation::tour-operators/create[]

[[resources-invite]]
==== Invite a Team Member

ADMIN+ only. Invites an email as ADMIN or STAFF (never OWNER) and sends an
accept link.

operation::tour-operators/invitations/create[]

[[resources-invitation-get]]
==== Get an Invitation

ADMIN+ only. A single invitation's detail — lifecycle `status` plus a computed
`expired` flag (a PENDING invitation past its window). 404 if the id isn't under
this operator.

operation::tour-operators/invitations/get[]

[[resources-invitation-resend]]
==== Resend an Invitation

ADMIN+ only. Mints a fresh accept link (the previous one stops working),
renews the expiry, and re-sends the email. Only a pending invitation can be
resent (accepted or revoked → 409); a lapsed pending invitation can.

operation::tour-operators/invitations/resend[]

[[resources-invitation-revoke]]
==== Revoke an Invitation

ADMIN+ only. Cancels a pending invitation — the accept link stops working.
Only a pending invitation can be revoked (accepted or already-revoked → 409).

operation::tour-operators/invitations/revoke[]

[[resources-invitation-preview]]
==== Preview an Invitation

Public — validates the emailed token before the accept form.

operation::invitations/preview[]

[[resources-invitation-accept]]
==== Accept an Invitation

Public. A new invitee provides a name + password and is auto-logged-in; an
already-authenticated user (matching email) simply joins.

operation::invitations/accept[]
